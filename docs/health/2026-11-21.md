## Findings

1. **Mic capture failures are silent, and a read error spins the capture thread** (medium, core)
   `PitchDetector.kt:39`, `PitchDetector.kt:47-53`, `MainActivity.kt:143-148`.
   - If `r.read` returns an error code (`ERROR_INVALID_OPERATION` when recording didn't actually start, for example because another app or a call holds the mic, or `ERROR_DEAD_OBJECT` after the audio server restarts), the inner loop breaks, `got < raw.size` hits `continue`, and the outer loop reads again straight away. That busy loop runs until `stopMic`, burning CPU and battery, and no frames reach the page.
   - If `AudioRecord` fails to initialise, the thread exits but `detector` stays non-null, so later `startMic()` calls never retry. In both cases the page has already been told `onMicState('on')`, so the screen looks deaf with no explanation.

   *Why it matters:* this is the app's main input. A busy mic (calls, voice assistants, another recorder) is common on a real phone, and the README already lists real-device testing as not yet done.
   *Fix (S–M):* stop the loop on any negative `read` result and check `r.recordingState` after `startRecording()`. Give `PitchDetector` an `onError` callback that clears `detector` and sends `onMicState('unavailable')` (or `'busy'`). Show it in the existing `#mic-msg` notice, and add the new state to the README's bridge list.

2. **A refused `AudioTrack` crashes the app** (high, rare)
   `MainActivity.kt:202-213`. `AudioTrack.Builder().build()` throws `UnsupportedOperationException` when the audio server can't create the track (resource limits, the audio server restarting). The call is outside the `try`, which only catches `IllegalStateException` around `write`/`play`. It runs on `toneThread`, so an uncaught exception kills the process.
   *Fix (S):* build inside the `try` and catch `UnsupportedOperationException` too, leaving `track` null. While you're in there, consider moving the clamping and the pluck synthesis (`MainActivity.kt:193-201`, `240-246`) into a small pure `Tone` object with no `android.*` imports, so the bridge's argument rules and the buffer length can be unit-tested like `Yin`.

3. **YIN's parabolic step can go far off at the top of the band** (medium, core)
   `Yin.kt:68-75`. Interpolation assumes `diff[tau]` is a local minimum of `a, b, c`. When the first dip is at `tauMin` (pitches near or above 1600 Hz, such as a whistle or a strong harmonic), `diff[tau-1]` lies outside the search and can be lower than `b`. Then `den` can be near zero or negative and the shift is unbounded, so `hz` can come out far off or even negative. A negative `hz` reaches JS, where `hzToMidi` gives `NaN` and the tuner shows an empty or wrong note.
   *Fix (S):* interpolate only when `b <= a && b <= c` (otherwise keep `tau`), or clamp the shift to ±1. Pin it in `YinTest` with a sine just above `MAX_HZ` (e.g. 1700 Hz), asserting the result is 0 or positive and within the band.

4. **The same small lists and logic written twice in the JS** (medium)
   - Major scale: `notes.js:52` (`V.notes.MAJOR`, used nowhere) and `courses.js:5`.
   - Black-key pitch classes: `chart.js:9` and `settings.js:5`.
   - Hold timing: `range.js:55-70` re-implements `Holder`'s fill-and-drain with its own `MAX_DT` (`range.js:7` vs `pitch.js:5`), so the range test and the warm-ups can drift apart in how "held" feels.
   - The "restart a CSS animation" idiom (`remove`, `void offsetWidth`, `add`) appears four times: `warmups.js:123`, `183`, `215` and `challenge.js:54`.

   *Why it matters:* each new screen copies one of these, and the next change to one copy misses the others.
   *Fix (S):* make `courses.js` use `V.notes.MAJOR` (or delete it), add `V.notes.isBlack`, add a `V.ui.replay(node, cls)` helper, and either drive the range test with `Holder` (target = the held note) or share `MAX_DT` from `pitch.js`.

5. **Challenge colours bypass the theme** (low)
   `holes.js:74-75` (sky gradient), `holes.js:79` (`dark ? '#ffffff' : '#ffffff'`, the same value either way), `holes.js:137`, `challenge.js:46` (`color:#fff`). `holes.js:160-161` works out dark mode by parsing `--bg` as hex, and `chart.js:119` `alpha()` also assumes `#rrggbb`. The README says `design/theme-canyon.json` is the only place colours are defined. A theme with a 3-digit or `rgb()` value would break both parsers quietly.
   *Fix (S):* add `sky1`, `sky2`, `star` (and use `ink` for the chip text) to the theme JSON, read them through `css()`, and tell dark mode from `matchMedia`/`data-theme` rather than the background's luminance.

6. **The Minor scale level is labelled "major"** (low)
   `challenge.js:58-59` always writes "<letter> major" in the subtitle and key stepper, including on the Minor scale level.
   *Fix (S):* give each level in `courses.js` a mode (`major`/`minor`) and use it in the header. The `courses` tests can pin it.

7. **Default challenge key can fall outside what the store accepts** (low)
   `challenge.js:18-24` vs `store.js:30`. For a range starting below about A♯1, `defaultRoot()` returns a tonic under 36. "Raise key" then calls `store.set('challengeRoot', root + 1)`, which the store rejects silently, so the button looks enabled but does nothing. Only the no-fit fallback (`challenge.js:23`) clamps.
   *Fix (S):* clamp the result of `defaultRoot()` to 36–72.

8. **Warm-up note timer counts time spent in the background** (low)
   `warmups.js:88-99`. `timer.from` uses `performance.now()`, which keeps running while the WebView is paused. If you leave the app on your turn and come back after the note time, `tick` calls `timeUp()` at once and the rep restarts. Separately, tapping a chip while paused (`warmups.js:212-213`) takes a second off `timer.used` even though the timer was frozen, so it gives back time that was never spent.
   *Fix (S):* stop the timer on `visibilitychange` when `document.hidden` and restart it when visible on your turn. Only give back preview time when the timer is running.

9. **Unused rungs-and-ball mode in `chart.js`** (low)
   `chart.js:14-15`, `56-68`, `88-97`, `138`, `144`. `setRungs` and `clear()` are never called. About 30 lines of drawing serve no screen and make the chart harder to read. ROADMAP "Next" already lists this.
   *Fix (S):* delete the `rungs`/`drop` paths, `setRungs`, `clear` and the `opts` parameter.

10. **Docs drift** (low)
    - README "Settings are stored…" lists the keys without `noteTime`.
    - ROADMAP's big-picture table (`docs/ROADMAP.md:15`) still says the challenge tolerance is "Easy / Medium / Strict". It's now a ±5–50 cent slider.
    - `warmups.js:24` has two comments run together: the `MISS_MS` comment ("how long the miss shows…") sits on the `PREVIEW_S` line.

    *Fix (S).*
