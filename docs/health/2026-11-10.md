## Findings

1. **Security: `playTone` doesn't validate its arguments and can crash the app** (high)
   `MainActivity.kt:93-125`. `seconds` and `hz` come straight from page JS. A NaN, zero or negative `seconds` gives a zero or negative buffer, so `AudioTrack.Builder().build()` or `ShortArray(n)` throws on a raw background thread, and that kills the process. A large `seconds` allocates `44100 × seconds` shorts and runs out of memory. The UI only sends sane values today, but the bridge is the contract and any future caller (or a bug in `a4`/`midi`) reaches it. The track also isn't released if `write`/`play` throws.
   *Fix (S):* reject non-finite values and clamp (e.g. `hz` 20–5000, `seconds` 0.05–5), wrap the work in `try/finally { track.release() }`.

2. **Mic can start while the app is in the background** (high, core/privacy)
   `MainActivity.kt:121`, `warmups.js:106-110`, `challenge.js:87`. The WebView isn't paused in `onPause` (no `web.onPause()` / `pauseTimers()`), so JS timers keep running. If the user leaves during a warm-up's playback, `playSequence`'s `onDone` → `turn()` → `refreshMic()` → `Android.startMic()` runs `startMic()` with the activity paused. That breaks the README's "only while the app is in the foreground", shows the mic indicator from the background, and on newer Android versions recording from the background is silenced or blocked anyway.
   *Fix (S):* in `startMic()` record the request (`wantMic`) but only start the detector when the activity is resumed (keep an `isResumed` flag set in `onResume`/`onPause`); also call `web.onPause()`/`web.onResume()`.

3. **Pitch detection maths has no tests and can't be unit-tested as written** (high, core)
   `PitchDetector.kt:75-115`. YIN (difference function, threshold, parabolic interpolation) and the 2:1 decimation live in the same class as `AudioRecord` and its thread. The README's "under 2 cents from 41 Hz to 1047 Hz" was checked once and nothing pins it. The JS core (`notes.js` `hzToMidi`/`span`/`voiceType`, `pitch.js` `Tracker`/`Holder`) is also untested.
   *Fix (M):* move `analyse` and decimation into a plain `Yin` class with no `android.*` imports that returns `(hz, clarity)`. Add JUnit tests feeding synthetic sines (41.2, 82.4, 110, 440, 1046.5 Hz) and asserting under 2 cents, plus silence and noise returning 0. For JS, a small Node test of `notes.js` and `Holder` would be enough.

4. **Reference tones use raw threads and `Thread.sleep`** (medium)
   `MainActivity.kt:115,125`. Each note starts a new `Thread` that sleeps for the tone's length to release the track. A warm-up sequence creates several overlapping threads and tracks, and a tone keeps playing after the user leaves the screen or app, since nothing can stop it.
   *Fix (S):* use one single-thread executor (or a `HandlerThread`), release via `setNotificationMarkerPosition`/`postDelayed` instead of sleeping, keep the current track so `stopMic`/`onPause` (or a new `Android.stopTone()`) can stop it.

5. **`stopMic` blocks the main thread for up to 500 ms** (medium)
   `PitchDetector.kt:67-71`, called from `onPause` on the UI thread. `rec.read` is blocking, so `join(500)` can stall each pause or screen change. If the join times out, the old thread still owns the `AudioRecord` while a new detector may start.
   *Fix (S):* call `rec.stop()` from `stop()` to unblock `read`, and don't join on the main thread (or join briefly after stopping).

6. **Detector callbacks can reach a destroyed WebView** (low)
   `MainActivity.kt:60,65`. `js()` posts to the UI thread from the audio thread; a frame queued just before `onPause`/`onDestroy` runs `evaluateJavascript` afterwards. Harmless today, but there's no `onDestroy` releasing the WebView or detector.
   *Fix (S):* add `onDestroy` that stops the detector and calls `web.destroy()`; skip `js()` when finishing.

7. **Mic denied leaves JS thinking the mic is on** (low)
   `audio.js:26-30`. After a denial `micOn` stays `true`, so `setMic(true)` is a no-op until the user changes screen. There's no way to ask again from the screen that showed "denied".
   *Fix (S):* reset `micOn` in `onMicState('denied')`, and offer a retry that calls `startMic` (or opens app settings when the denial is permanent).

8. **targetSdk 35 is behind** (medium; high once the app heads for Play)
   `app/build.gradle.kts:11`, lint `OldTargetApi`. Play requires new apps and updates to target a recent level (API 36 from August 2026).
   *Fix (S):* move compileSdk/targetSdk to 36, check edge-to-edge and back handling (predictive back becomes the default, see 9).

9. **Deprecated `onBackPressed`** (low)
   `MainActivity.kt:50-56`. It's suppressed rather than replaced with `OnBackInvokedCallback`; on targetSdk 36 with predictive back, `onBackPressed` stops being called.
   *Fix (S):* register an `OnBackInvokedDispatcher` callback (API 33+), keep the old path below that.

10. **No Gradle wrapper and no checksum** (low)
    Repo root. `gradlew`, `gradle-wrapper.jar` and `distributionSha256Sum` are missing, so builds depend on a locally cached Gradle and the download isn't verified.
    *Fix (S):* run `gradle wrapper --gradle-version 8.11.1 --gradle-distribution-sha256-sum <sum>` and commit the wrapper.

11. **Lint hygiene** (low)
    `AndroidManifest.xml:13` locks portrait (`LockedOrientationActivity`, `DiscouragedApi`), `res/mipmap-anydpi-v26` is redundant at minSdk 26 (`ObsoleteSdkInt`). The portrait lock is a reasonable choice for this UI; if so, add a lint baseline or `tools:ignore` with a reason.
    *Fix (S).*

12. **Security: WebView hardening and release build** (low)
    `MainActivity.kt:29-34`, `app/build.gradle.kts:15`, manifest. File access is left at its default (on below API 30), there's no `WebViewClient` blocking navigation away from the bundled page, `allowBackup` is unset (only settings are stored, so backup is fine but should be a decision), release minify is off, and `.gitignore` lacks `*.jks`/`*.keystore`.
    *Fix (S):* `allowFileAccess = false` with `WebViewAssetLoader` (or keep `file://` and note why), a `WebViewClient` that only allows `file:///android_asset/`, explicit `allowBackup`, `isMinifyEnabled = true` for release, add keystore patterns to `.gitignore`.
